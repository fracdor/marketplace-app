## Content (approved)

### Testing
- Every `fireEvent.*` call must be `await`ed (not just `press`, also `changeText`) — confirmed RNTL v14 + RN 0.86 + React 19 quirk; unawaited calls corrupt `act()` tracking across test boundaries.
- `jest` pinned to `^29` (`jest-expo@57` constraint); `test-renderer` is a real dependency, not a typosquat.
- Running `npm test` from the repo root while another worktree exists under `.claude/worktrees/` or `.worktrees/` inflates/duplicates the test count — use `--testPathIgnorePatterns "/node_modules/|/\.claude/"`.
- Always verify test counts live; never trust a number from a prior memory or plan document.

### RLS/Supabase
- RLS-reachability reasoning (which role×status combinations are actually reachable) has caught real bugs repeatedly — apply it before assuming a state "can't happen."
- A row hidden by RLS on an embedded/joined relation comes back `null`, not an inaccessible object — treat `null` as a meaningful signal, not just missing data.
- `profiles_public` can't be embedded directly from `tasks` in PostgREST (no FK) — client info is fetched via a separate query.
- RLS policies/triggers are the real defense-in-depth behind any UI-level restriction — verify the policy/trigger itself, not just that a button is hidden.

### React Query
- `xKeys` factory pattern (`all` / `lists()` / `list(filter)` / `detail(id)`) with prefix-based invalidation.
- `staleTime: Infinity` for static catalogs.
- A single shared `pending` state per hook (not per row) that disables an entire list during one mutation is an accepted MVP-scale tradeoff.

### Componentes
- Exhaustive switches with no `default` case over `TaskStatus`-like unions (compile error if a case is missed, not a silent mis-render).
- Sibling `Pressable`s, not nested ones (avoids touch-propagation bugs).
- `router.replace` (not `push`) after completing a form and leaving the screen.
- Every mutation call site needs `mapAuthError` + inline error text — none should fail silently.
- Confirmation dialogs use `'Volver'`/`'Sí, <acción>'` button pairs, never two ambiguous "Cancelar"-type buttons.

### Flujo de trabajo
- brainstorming → spec → plan → subagent-driven-development, TDD throughout.
- Every reviewer-subagent dispatch must include the read-only-git instruction.
- A final holistic (whole-branch) review catches integration issues per-task review misses.
- `npm install` is mandatory after merging a branch that added dependencies, before trusting `tsc`/tests on `main`.
